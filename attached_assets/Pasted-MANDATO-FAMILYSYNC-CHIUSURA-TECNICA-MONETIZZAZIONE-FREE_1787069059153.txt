1. RIMUOVERE IL BYPASS AI DEGLI ADMIN

Nel file server/lib/ai-usage.ts è presente una logica che rende di fatto illimitata la quota AI degli amministratori della famiglia tramite Number.MAX_SAFE_INTEGER.

Rimuovere completamente questa eccezione.

La quota AI deve dipendere ESCLUSIVAMENTE dal piano della famiglia:
- Free -> PLAN_LIMITS.free
- Premium -> PLAN_LIMITS.premium

Il ruolo admin NON deve modificare le quote AI.

Gli account proprietario/VIP/tester eventualmente Premium devono continuare a ottenere Premium tramite il sistema entitlement già esistente, non tramite il ruolo famiglia.

Aggiornare i test interessati e aggiungere un test esplicito che dimostri:
- admin di famiglia Free -> rispetta PLAN_LIMITS.free;
- admin di famiglia Premium -> rispetta PLAN_LIMITS.premium.


2. RENDERE ILLIMITATE NEL FREE LE FUNZIONI COLLABORATIVE DI BASE

Attualmente server/lib/base-usage.ts applica BASE_FREE_DAILY_LIMIT = 5 a:
- calendario;
- articoli spesa;
- faccende;
- messaggi chat.

Questo limite deve essere eliminato.

Calendario, spesa, faccende e chat devono essere illimitati sia nel piano Free sia nel Premium.

Non introdurre un limite alternativo (10, 20, 50 ecc.).

Rimuovere/disattivare in modo pulito:
- reserveBaseSlot come meccanismo di blocco delle operazioni;
- risposte FREE_DAILY_LIMIT_REACHED;
- contatori base:* utilizzati esclusivamente per applicare tale limite.

Non modificare le normali autorizzazioni, validazioni o controlli di sicurezza di tali endpoint.

Se alcune strutture devono essere mantenute temporaneamente per compatibilità, non devono più impedire alcuna operazione.

Aggiornare i relativi test.


3. MANTENERE LE ATTUALI QUOTE AI FREE/PREMIUM

NON modificare in questo mandato i valori di PLAN_LIMITS Free/Premium già presenti, salvo ciò che è strettamente necessario per eliminare il bypass admin.

Le quote AI continuano a essere condivise secondo la logica attuale e devono continuare a essere contabilizzate prima della chiamata OpenAI.


4. MANTENERE GLI ALTRI LIMITI FREE/PREMIUM ESISTENTI

Mantenere:

5. CORREGGERE L'INIZIALIZZAZIONE REVENUECAT

Nel file lib/revenuecat.tsx la funzione che seleziona la API key verifica oggi contemporaneamente la presenza di:
- test key;
- iOS key;
- Android key.

Correggere la logica affinché richieda SOLO la chiave necessaria al contesto corrente:

- modalità test / Expo Go / web -> EXPO_PUBLIC_REVENUECAT_TEST_API_KEY;
- build iOS reale -> EXPO_PUBLIC_REVENUECAT_IOS_API_KEY;
- build Android reale -> EXPO_PUBLIC_REVENUECAT_ANDROID_API_KEY.

Una build Android non deve fallire perché manca la chiave iOS e viceversa.

Mantenere un errore chiaro e fail-fast se manca proprio la chiave richiesta per la piattaforma corrente.

Aggiungere test, se tecnicamente praticabile, o almeno separare la selezione della key in funzione pura testabile.
