Abbiamo deciso di semplificare strutturalmente il Piano Pasti di FamilySync.

La gestione libera di:

```text
Allergie / intolleranze
```

deve essere rimossa completamente dal Piano Pasti.

Al suo posto voglio un unico campo:

```text
Dieta
```

con menu a tendina e profili predefiniti/testabili.

L’obiettivo è eliminare la complessità e le regressioni generate dalla combinazione libera di allergeni, mantenendo però due esigenze alimentari importanti come profili dieta espliciti:

* senza glutine;
* senza lattosio.

NON fare deploy.

# 1. NUOVO MODELLO FUNZIONALE

Il Piano Pasti deve avere un solo selettore principale:

```text
Dieta
```

Non deve più esistere un campo separato:

```text
Allergie / intolleranze
```

Il menu a tendina deve contenere almeno questi profili:

```text
Mediterranea
Mediterranea senza glutine
Mediterranea senza lattosio
Vegetariana
Vegetariana senza glutine
Vegana
```

Se nel progetto esistono già altre diete generali stabili e supportate, elencale nel report prima di decidere se mantenerle.

Non introdurre nuove combinazioni libere.

# 2. NIENTE PIÙ CAMPO LIBERO ALLERGENI

Rimuovi completamente dalla UI:

```text
Allergie / intolleranze (opzionale)
```

e tutto ciò che lo supporta:

* input;
* placeholder;
* icona;
* stato React;
* form binding;
* validation;
* parsing;
* submit;
* reset;
* salvataggio;
* precompilazione;
* voice parsing specifico allergeni.

Nessun utente deve poter inserire:

```text
glutine
lattosio
uova
frutta a guscio
pesce
soia
...
```

in un campo separato.

# 3. WEB + MOBILE

Applica la stessa modifica a:

* web;
* Expo/mobile;
* componenti condivisi;
* eventuali modali;
* Genera alternativa;
* modifica piano;
* piani salvati;
* eventuali schermate di onboarding o preferenze.

Non lasciare il campo allergeni in una piattaforma e rimuoverlo solo nell’altra.

# 4. PROFILI DIETA CANONICI

Crea identificatori interni stabili, per esempio:

```ts
mediterranean
mediterranean_gluten_free
mediterranean_lactose_free
vegetarian
vegetarian_gluten_free
vegan
```

I label mostrati all’utente devono essere localizzati.

Esempio IT:

```text

Mediterranea senza lattosio
Vegetariana
Vegetariana senza glutine
Vegana
```

Non usare il testo UI come unica logica di business.

# 5. NIENTE COMBINAZIONI LIBERE

NON creare una struttura del tipo:

```text
diet = mediterranea
modifier = gluten_free
modifier = lactose_free
```

se questo permette nuovamente combinazioni arbitrarie non testate.

Ogni voce del menu deve rappresentare un profilo completo e predefinito.

Esempio:

```text
Mediterranea senza glutine
```

deve essere un profilo autonomo e testato end-to-end.

# 6. PROFILO MEDITERRANEA

Il profilo:

```text
Mediterranea
```

deve poter utilizzare normalmente:

* pasta;
* pane;
* riso;
* cereali;
* patate;
* polenta;
* carne bianca;
* carne rossa;
* pesce;
* uova;
* formaggi;
* latticini;
* legumi;
* frutta;
* verdura;
* olio EVO.

Mantieni una rotazione varia tra pranzo e cena.

# 7. CARNE ROSSA NELLA MEDITERRANEA

Per:

```text
Mediterranea
```

in una settimana di 7 giorni deve esserci:

```text
almeno 1 pasto principale con carne rossa
```

a pranzo oppure a cena.

Il requisito vale quando non esistono altri vincoli del profilo che lo impediscano.

La carne rossa non deve diventare dominante.

Mantieni una rotazione tra:

* pesce;
* carne bianca;
* carne rossa;
* uova;
* legumi.

# 8. PROFILO MEDITERRANEA SENZA GLUTINE

Questo profilo NON deve funzionare come:

```text
elimina pasta
elimina pane
elimina prodotti da forno
```

Deve funzionare come:

```text
mantieni le famiglie alimentari mediterranee
+
sostituisci i prodotti contenenti glutine con equivalenti esplicitamente senza glutine
```

Esempi:

```text
pasta → pasta senza glutine
pane → pane senza glutine
biscotti → biscotti senza glutine
crackers → crackers senza glutine
gnocchi → gnocchi senza glutine
pangrattato → pangrattato senza glutine
couscous → variante esplicitamente senza glutine, se supportata
farine → farine senza glutine compatibili
```

Mantieni anche alimenti naturalmente senza glutine:

* riso;
* mais/polenta;
* patate;
* quinoa;
* carne;
* pesce;
* uova;
* formaggi;
* legumi;
* frutta;
* verdura.

Il risultato deve restare riconoscibile come dieta mediterranea.

# 9. GLUTEN-FREE: NIENTE FILTRO TROPPO RESTRITTIVO

Non ricreare il vecchio problema in cui:

```text
senza glutine
```

porta quasi esclusivamente a:

* riso;
* patate;
* quinoa;
* polenta.

Il profilo deve mantenere una vera varietà culinaria.

Deve poter produrre anche:

* pasta senza glutine;
* pane senza glutine;
* gnocchi senza glutine;
* prodotti da forno GF esplicitamente compatibili;
* altri sostituti previsti dal catalogo.

# 10. PROFILO MEDITERRANEA SENZA LATTOSIO

Questo profilo deve distinguere chiaramente:

```text
senza lattosio
```

da:

```text
senza latte
```

Non trattarlo come allergia alle proteine del latte.

Il profilo può utilizzare, se già supportati:

* latte senza lattosio;
* yogurt senza lattosio;
* formaggi/latticini esplicitamente senza lattosio;
* altri prodotti compatibili.

Deve continuare a poter utilizzare normalmente:

* pasta;
* pane;
* riso;
* carne;
* pesce;
* uova;
* legumi;
* frutta;
* verdura.

Non deve collassare su pochi piatti ripetitivi.

# 11. PROFILO VEGETARIANA

Mantieni:

```text
Vegetariana
```

come dieta generale.

Deve escludere carne e pesce secondo la policy già esistente.

Può includere, se previsto:

* uova;
* latte;
* formaggi;
* legumi;
* cereali;
* pasta;
* pane;
* verdure;
* frutta.

# 12. PROFILO VEGETARIANA SENZA GLUTINE

Questo profilo deve applicare contemporaneamente:

```text
vegetarian
+
gluten-free substitutions
```

ma non tramite combinazioni libere dell’utente.

È un profilo fisso e testato.

Deve poter usare:

* pasta senza glutine;
* pane senza glutine;
* riso;
* quinoa;
* polenta;
* patate;
* legumi;
* uova;
* formaggi;
* latticini;
* verdure;
* frutta;

se coerenti con il profilo.

# 13. PROFILO VEGANA

Mantieni la dieta:

```text
Vegana
```

secondo la policy già esistente.

Non introdurre carne, pesce, uova, latte o derivati.

In questo mandato NON creare automaticamente:

```text
Vegana senza glutine
Vegana senza lattosio
```

a meno che siano già profili realmente esistenti e testati.

Evita di ricominciare con una matrice combinatoria di diete.

# 14. ARCHITETTURA: PROFILO → CATALOGO COMPATIBILE

La nuova pipeline deve essere concettualmente:

```text
profilo dieta selezionato
        ↓
catalogo ingredienti/famiglie compatibili
        ↓
blueprint settimanale
        ↓
OpenAI
        ↓
validazione finale
```

Non:

```text
utente scrive allergeni liberamente
        ↓
OpenAI interpreta
        ↓
validator tenta di correggere
        ↓
retry
```

# 15. OPENAI NON DEVE DECIDERE LA COMPATIBILITÀ

Per i profili:

```text
Mediterranea senza glutine
Mediterranea senza lattosio
Vegetariana senza glutine
```

il backend deve predisporre prima un pool compatibile.

OpenAI deve generare ricette coerenti con quel pool.

Non affidare al modello la decisione se:

```text
pasta
pane
formaggio
couscous
```

siano compatibili.

Il profilo deve già stabilire quale variante utilizzare.

# 16. SOSTITUZIONI ESPLICITE

Crea una mappa deterministica delle sostituzioni.

Esempio concettuale:

```ts
glutenFreeSubstitutions = {
  pasta: ["pasta senza glutine", "pasta di mais/riso senza glutine"],
  bread: ["pane senza glutine"],
  breadcrumbs: ["pangrattato senza glutine"],
  gnocchi: ["gnocchi senza glutine"],
  biscuits: ["biscotti senza glutine"]
}
```

e per lactose-free:

```ts
lactoseFreeSubstitutions = {
  milk: ["latte senza lattosio"],
  yogurt: ["yogurt senza lattosio"],
  dairy: ["prodotti esplicitamente senza lattosio già supportati"]
}
```

Non inventare prodotti non presenti nel catalogo senza documentarlo.

# 17. VALIDAZIONE FINALE

Mantieni una validazione finale, ma semplificata e specifica per il profilo.

Per:

```text
Mediterranea senza glutine
```

verifica che eventuali prodotti normalmente contenenti glutine siano esplicitamente qualificati come gluten-free.

Per:

```text
Mediterranea senza lattosio
```

verifica che eventuali prodotti lattiero-caseari siano compatibili con il profilo.

La validazione è una barriera finale, non il meccanismo principale.
