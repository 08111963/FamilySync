La selezione attuale:

role === "admin" → OpenAI diretto

NON corrisponde alla richiesta “Fase 1 — solo il mio account”.

Nel progetto `admin` è il ruolo della membership nella singola famiglia.
Quindi qualsiasi utente amministratore della propria famiglia potrebbe essere instradato verso la mia OPENAI_API_KEY.

Questo non è accettabile.

CORREGGI ESCLUSIVAMENTE IL CRITERIO DI PILOT.

1. NON usare familyMembers.role === "admin" come criterio per OpenAI diretto.

2. Introduci una allowlist server-side configurabile tramite environment variable/Secret, per esempio:

OPENAI_DIRECT_PILOT_USER_IDS

Formato:
lista di user ID interni separati da virgola.

Esempio concettuale:
user-id-1,user-id-2

NON inserire email, nomi o user ID reali nel codice.

3. Il routing deve diventare:

se req.user.userId è presente in OPENAI_DIRECT_PILOT_USER_IDS
e OPENAI_API_KEY è configurata
→ provider = openai_direct

altrimenti
→ provider = replit_managed

4. Il ruolo familiare admin/adult/teen/child NON deve influenzare la scelta del provider.

Un utente non presente nella allowlist deve usare Replit Managed AI anche se è admin della propria famiglia.

5. Mantieni:
- client separati;
- OPENAI_API_KEY solo backend;
- Replit baseURL solo per replit_managed;
- background job sempre Replit;
- budget Piano Pasti = 28;
- quote applicative;
- nessuna modifica prompt/modelli/UI/database.

6. Se OPENAI_DIRECT_PILOT_USER_IDS è assente o vuota:
→ tutti gli utenti devono usare Replit Managed AI.

7. Se un user ID è nella allowlist ma OPENAI_API_KEY manca:
→ fallback a Replit Managed AI.
